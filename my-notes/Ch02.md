# Notes on Chapter 2.

My first action in the project (after cloning the repo, and making sure that the virtual environment is 
properly initialized) was to try a simplest python code in one of existing notebooks. I added
a new cell at the top and tried to execute it. VsCode asked me to create a venv - total surprize
(I expected I already have it). This is what Claude explained to me:

>> That's the classic VS Code notebook symptom: the folder having a working .venv on disk doesn't mean VS Code's notebook UI is pointed at it — those are two separate things.

>> What's happening: There's no .vscode/settings.json in this repo, so nothing tells VS Code which interpreter is "the" one for this workspace. When you ran the cell, the notebook had no kernel selected yet, and VS Code's kernel-picker flow (especially with the newer "Python Environments" extension) defaults to offering "Create Environment" rather than silently discovering .venv/Scripts/python.exe — even though your uv-created venv (confirmed: Python 3.13, ipykernel already installed at .venv/Lib/site-packages) is perfectly usable.

So I added the missing settings file as per CLAUDE recommandation.

Maybe it is obvious for other readers, but this cost me some time to start the real work.
